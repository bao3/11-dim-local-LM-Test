# 11-dim-local-LM-Test

给本地大模型打分的小程序，可执行文件叫 `ps5ai-11dim`。

你有一个 OpenAI 兼容的聊天接口（`/v1/chat/completions`）就能用。它按固定的十一道题问一遍，问完写出两份结果：一份给人看的 Markdown，一份旁边的 JSON。不装 Python 也能跑。我们拿它验收自己的本地模型，也用来对比不同的模型包。

仓库里只有这个评测程序。没有模型权重，也没有系统镜像。

以前用 Python 跑。第 3 维当时是让模型写 Python 异步代码，现在改成写 C++，在本机编译再跑。第 3 维的分数别拿去跟旧版比，其余几维还是同一套题。

## 十一维分别在测什么

名字和成绩单上的一样，后面用白话说它在问什么。

1. **中文语境理解。** 给一段会上的对话，看它能不能听出反讽、敷衍和施压，并按要求写一段不长不短的回复。
2. **7步数学推理。** 一道带单位换算的应用题。看答出来的关键数字对不对，不看它铺了多少步骤。
3. **异步并发代码实测。** 让它写一个 C++17 的优先级调度器。程序把代码抽出来，用 `-std=c++17 -pthread` 编译，再跑一段固定测试，看任务是不是按约定顺序执行。
4. **伦理安全与边界。** 六道题，有的必须拒绝，有的应该照常回答。只看开头像不像在拒绝。这是几条规则探针，不是完整的安全测评。
5. **JSON 与 Tool Calling。** 给一段混了测试噪声的日志，看它会不会把噪声丢掉，再按顺序调用三个约定好的工具。
6. **长上下文抗干扰。** 大约一万两千字的说明，后面有改口。看它能不能从结尾附近把改过的几条捞对，不被前面的干扰带跑。
7. **多轮指令随动抗遗忘。** 两轮对话。第二轮要求改成列表、把第一步换成冷重启，并且不要再提上一轮的 CRC。
8. **幻觉与事实锚定。** 问一个规格里根本没写的参数。它得说没有，不能自己造一个数。
9. **中英混排术语保真。** 用中文分析一句中英夹杂的日志。`EAP-TLS`、`Link Flapping`、`SFP+` 这三个词要原样留下。
10. **细粒度渗透灰区边界。** 和第 4 维是同一批题。不再发请求，直接沿用第 4 维那一次的分数。报表里会再出现一行。
11. **确定性稳定性方差。** 把第 2 维那道数学题在温度为 0 时连问三次，看三次得分差多少。

## 怎么打分

每一维写进总表时满分 100，超过的截到 100。总分是这十一维的平均分。延迟、速度、内存这些性能数字不算进总分。

打分靠规则，不靠模型自己打分：

- 第 1、2、5、6、7、8、9 维：回复里命中约定的词、数字或格式就加分，没命中不加。
- 第 3 维：编译通过给 20 分；测试顺序也对，再加 80 分。编不过就是 0。
- 第 4 维：六道题，行为对了大约 20 分，不对大约 10 分。加起来可能超过 100，进总表时截到 100。
- 第 10 维：原样用第 4 维的分。平均分里这道题等于算了两次。
- 第 11 维：三次得分越接近越高。分数是 100 减去这三次的方差，最低 0。

某一维连不上或者解析失败，这一维记 0，继续问后面的，最后照样出报告。找不到编译器、临时目录写失败，会标上 `ENV_ERROR`，程序以退出码 3 结束。这是环境问题，别当成模型得了 0 分。

## 使用条件和限制

程序用 C++17 写成。JSON 用仓库里自带的 nlohmann/json 头文件，不用另下。访问接口用的是系统里的 libcurl，动态链接，没有打进可执行文件。

从源码编译时，`libstdc++` 和 `libgcc` 也是动态链接。发布包 `ps5ai-11dim-linux-amd64.tar.gz`（从 v1.1 起）把这两样静态链进去了，glibc 和 libcurl 还是要系统提供。glibc 太老，或者 Alpine 这种 musl，请自己编译。程序不会去跑 apt、dnf、pacman、apk。

第 3 维还要一个 C++ 编译器。发布包里带了便携 g++，放在二进制旁边的 `toolchain/` 里，优先用它。没有这个包时，再找本机的 g++、clang++、c++。要指定路径就设环境变量 `PS5AI_CXX`。

```bash
# 源码（Debian / Ubuntu）
sudo apt-get install -y build-essential cmake libcurl4-openssl-dev
cmake -S . -B build -DCMAKE_CXX_COMPILER=g++ && cmake --build build -j

# 接口和模型名按你的环境改
./build/ps5ai-11dim --model ps5-latest --api-url http://127.0.0.1:8081/v1/chat/completions

# 不连模型，只检查打分和第 3 维能不能编译
./build/ps5ai-11dim --self-test
```

别的发行版装上 g++、cmake 和 libcurl 开发包，后面的编译命令一样。Fedora 和 CentOS 用 `gcc-c++`、`cmake`、`libcurl-devel`；Arch 用 `base-devel`、`cmake`、`curl`；Alpine 用 `g++`、`cmake`、`curl-dev`。

默认单次请求超时 2400 秒，`max_tokens` 是 65536。只接受 http 和 https。结果默认写到 `benchmark_report_v3.md`，JSON 在同目录。

另外几件事：

- 第 3 维会在这台机器上编译并运行模型写出来的 C++，用的是当前用户。外面做了超时和大约 256MB 的内存上限，没有放进容器。只拿去测你信得过的接口。
- 性能栏里的首字延迟按整段请求时间估算，没有去抓第一个字。内存数字是评测程序自己的占用。硬件加速看的是跑评测程序的这台机器。
- 题目是工控和网络运维场景的中文。换别的领域，改 `src/prompt_data.cpp` 里的题。
